## 1. Введение и подготовка рабочего места

Эта практическая работа поможет вам с нуля написать настоящую программу на языке C# — консольное приложение «Библиотека». Программа покажет книги и читателей, выдаст книгу, примет её обратно и посчитает статистику. Вы пройдёте весь путь разработчика: от создания проекта одной командой в терминале до готового приложения с меню. Работа рассчитана на два занятия (две пары) и не требует никаких знаний C# — всё нужное объясняется по ходу дела.

Все действия выполняются в редакторе Visual Studio Code и в терминале — без кнопок, мастеров и диалоговых окон. Именно так работают профессиональные разработчики: команды терминала одинаковы на Windows, macOS и Linux, и этот навык пригодится вам в любом следующем проекте. Если на лекциях вам показывали тяжёлую студию с сотней кнопок — забудьте её: четыре команды `dotnet` закрывают всё, что нужно новичку.

### 1.1. Как пользоваться документом

Сначала прочитайте образец (раздел 2) и мини-справочник (раздел 3): они показывают приёмы, которыми вы будете пользоваться всю работу. Затем выполняйте задания из разделов 4 и 5 по порядку. Каждое задание — это отдельный файл с классом: читаете требования, создаёте файл, сами пишете класс, сохраняете (Ctrl+S) и проверяете сборкой в терминале. Готового кода в заданиях нет: в них перечислены имена полей и методов и описано нужное поведение, а как записать это на C# — подсказывают образец и справочник. Не переходите к следующему заданию, пока предыдущее не собралось без ошибок: ошибка, пропущенная сейчас, превратится в три ошибки через двадцать минут.

Комментарии после двух наклонных черт `//` объясняют код и не влияют на программу, но набирать их в своих классах полезно: так вы учитесь читать и структурировать код.

## 2. Образец для разогрева: телефонная книга

Прежде чем строить библиотеку, соберите маленький проект по готовому образцу. Это единственное место во всей работе, где код дан полностью: разберите его вместе с преподавателем и наберите своими руками — дальше вы будете писать классы самостоятельно, по требованиям заданий. В образце всего два класса, но уже видны главные приёмы: класс как контейнер данных, объект внутри объекта, вызовы методов и запуск программы из терминала. Не копируйте текст, а печатайте: так руки запоминают синтаксис. На образец уходит 20–30 минут, и он окупится на обоих занятиях.

### 2.1. Создаём проект в терминале

Откройте терминал в удобной папке (например, Документы или Рабочий стол) и выполните четыре команды. Команда `dotnet new console` создаст папку PhoneBook с проектом внутри.

В папке проекта появились два важных файла: PhoneBook.csproj — описание проекта, его изменять не нужно, и Program.cs — стартовый код. Команда `dotnet run` собрала проект и запустила его, поэтому терминал напечатал Hello, World!. Раз получилось — окружение работает, и можно добавлять свои файлы. Создайте два файла командами `code Contact.cs` и `code PhoneBook.cs` и наберите в них листинги ниже.

### 2.2. Класс Contact — один контакт

В классе Contact два public-поля и один метод Print. Метод ничего не возвращает, поэтому перед именем стоит слово void. Внутри метода поля используются напрямую — Name и Phone, ведь метод принадлежит тому же классу.

```csharp
// Contact.cs - один контакт телефонной книги
public class Contact
{
    public string Name;    // имя
    public string Phone;   // телефон

    public void Print()
    {
        Console.WriteLine(Name + " - " + Phone);
    }
}
```

### 2.3. Класс PhoneBook — объект внутри объекта

Здесь впервые виден приём «объект внутри объекта»: поля First и Second — это не числа и не строки, а ссылки на объекты Contact. Книга сама не создаёт контактов — она лишь хранит те, что положили снаружи, и умеет печатать их по очереди. В задании 4 тот же приём понадобится для выдачи: объект Loan будет хранить книгу и читателя одновременно.

```csharp
// PhoneBook.cs - книга хранит два контакта
public class PhoneBook
{
    public Contact First;    // первый контакт
    public Contact Second;   // второй контакт

    public void PrintAll()

        Console.WriteLine("В книге два контакта:");
        First.Print();
        Second.Print();
    }
}
```

### 2.4. Программа Program.cs и запуск

Замените всё содержимое Program.cs на листинг ниже. Строки программы выполняются по порядку, сверху вниз: создаётся книга, затем два контакта, каждый заполняется по полям и занимает своё место в книге, в конце печатается всё сразу.

## 3. Мини-справочник: восемь тем

Ниже собраны все конструкции языка, которые нужны в практической работе. Каждая тема — короткое объяснение и мини-пример. Возвращайтесь к этому разделу, когда в заданиях что-то будет непонятно: не нужно ничего искать в интернете, всё под рукой. Если тема понятна с первого раза — смело переходите к следующей, глубокая теория вам пока не нужна.

### 3.1. Класс, объект и поля

Класс — это чертёж, объект — конкретная вещь, сделанная по чертежу. Из одного класса Book можно создать сколько угодно объектов-книг, и у каждого будут свои значения полей. Поля объявляются внутри класса, а у объекта читаются и меняются через точку. Слово new создаёт объект в памяти.

```csharp
Book b = new Book();          // создали объект по чертежу Book
b.Title = "Азбука";           // записали значение в поле
b.Year = 1872;
Console.WriteLine(b.Title);   // прочитали поле
b.Print();                    // вызвали метод
```

### 3.2. public и private

Слова public и private отвечают на вопрос «кто видит поле или метод». public — доступно откуда угодно, private — только изнутри собственного класса. Правило хорошего тона: данные прячут, а наружу выставляют методы, которые проверяют значение перед записью. Так данные объекта нельзя испортить случайно.

```csharp
public class Person
{
    private int age;                       // видно только внутри

    public void SetAge(int value)          // запись - через метод
    {
        if (value < 0)
        {
            age = 0;                       // защита от мусора
        }
        else
        {
            age = value;
        }
    }

    public int GetAge()                    // чтение - через метод
    {
        return age;
    }
}
```

В нашем проекте ровно так устроен класс Reader: номер билета спрятан, а снаружи доступны методы SetTicket и GetTicket. Такой приём называется инкапсуляцией — о нём вы услышите на лекциях, а здесь увидите вживую. Тем же приёмом в задании 8 будет спрятан счётчик выдач библиотеки.

### 3.3. Методы, параметры, return

Метод — это действие, которое умеет объект. Если метод должен вернуть результат, в объявлении пишут тип результата, а внутри используют return; если возвращать нечего, пишут void. Значения в скобках называются параметрами — это данные, которые метод получает снаружи.

```csharp
public int Sum(int a, int b)    // принимает два числа
{
    return a + b;               // возвращает результат
}

public void PrintLine()         // void - ничего не возвращает
{
    Console.WriteLine("---------");
}

int s = Sum(2, 3);              // s = 5
```

### 3.4. static — методы самого класса

Обычные методы вызывают у объекта. Статические (static) методы принадлежат самому классу и вызываются по имени класса, без создания объекта. Статическими удобно делать маленькие помощники: ввод данных, работу с датами, статистику. В проекте четыре static-класса: InputHelper, DateHelper, StatsHelper и DataInitializer.

```csharp
public static class MyMath
{
    public static int Double(int x)
    {
        return x * 2;
    }
}

int d = MyMath.Double(21);      // d = 42, объект создавать не нужно
```

### 3.5. if / else if / else

Конструкция if проверяет условие и выполняет блок, только если условие истинно. else if добавляет следующую проверку, а else срабатывает, когда ни одно условие не подошло. Условия сравнивают значения: `==` означает «равно», `!=` — «не равно», `>` и `<` — «больше» и «меньше», `>=` и `<=` — с приставкой «или равно». Не путайте `==` (сравнение) с `=` (присваивание) — это самая частая ошибка новичков.

```csharp
if (year < 1900)
{
    Console.WriteLine("Старинная книга");
}
else if (year < 2000)
{
    Console.WriteLine("Книга XX века");
}
else
{
    Console.WriteLine("Современная книга");
}
```

### 3.6. Цикл for

Цикл for повторяет блок заданное число раз. В скобках через точку с запятой стоят три части: подготовка счётчика, условие продолжения и шаг после каждого повтора. В этой работе цикл for нарисует разделительные линии в Printer, даст три попытки на ввод числа в InputHelper и построит штрих-диаграмму в StatsHelper.

```csharp
for (int i = 1; i <= 5; i = i + 1)
{
    Console.WriteLine("Строка номер " + i);
}
// напечатает пять строк: с номером 1 до номера 5
```

Запись `i = i + 1` увеличивает счётчик на единицу; короче то же самое пишут как `i++`. В листингах работы используется полная форма, чтобы было очевидно, что именно происходит, — обе формы правильные.

### 3.7. Ввод с клавиатуры: Console.ReadLine и int.TryParse

Console.ReadLine() всегда возвращает строку — даже если пользователь ввёл цифры. Чтобы работать с числом, строку превращают в int командой int.TryParse: она получает строку, пытается разобрать число и отвечает true или false через параметр out. Никогда не доверяйте вводу: пользователь может ввести слово «двадцать» вместо числа 20.

```csharp
Console.Write("Введите число: ");
string input = Console.ReadLine();        // это всегда ТЕКСТ

int number;
bool ok = int.TryParse(input, out number);
if (ok)
{
    Console.WriteLine("Получилось: " + number);
}
else
{
    Console.WriteLine("Это не число!");
}
```

В задании 5 эта проверка ляжет в основу InputHelper.ReadInt: у пользователя будет три попытки ввести корректное число, а потом метод честно признается, что попытки закончились.

### 3.8. Счётчик: как программы считают

Слово «рядом» в PrintSummary значит: сначала Console.Write с текстом и числом без переноса строки, потом вызов Bar — штрихи лягут в ту же строку. Обратите внимание на последнюю строку сводки: private-счётчик totalIssues из задания 8 нельзя прочитать напрямую — только через публичный метод. Это инкапсуляция из раздела 3.2 в действии.

**Проверка.** Вызовите в Program.cs PrintSummary для библиотеки из задания 8: числа в статистике должны совпасть с реальностью — сколько книг зарегистрировано, сколько на полке, сколько читателей и сколько раз сработала выдача. При AvailableBooks = 0 напротив «на полке» должно стоять слово «(нет)».

### Задание 10. DataInitializer и Program: меню библиотеки

Финальные два файла. DataInitializer — фабрика тестовых данных: создаёт готовые книги и читателей, чтобы не набивать их вручную. Program.cs становится настоящей программой с меню: печатает пункты, читает номер и выбирает действие. Стартовый Program.cs переписывается целиком — временные тесты заданий 2–9 больше не нужны.

Создайте файл `DataInitializer.cs`:

```text
$ code DataInitializer.cs
```

**Требования к классу DataInitializer.**

- класс объявляется как `public static class DataInitializer`;
- `public static Book MakeBook(int number)`: создаёт Book и заполняет поля — Title «Книга номер number», Author «Автор номер number», Year равен 2000 + number, IsAvailable равно true; возвращает объект;
- `public static Reader MakeReader(string fullName, string ticket)`: создаёт Reader, задаёт FullName, вызывает SetTicket(ticket) и возвращает объект.

**Подсказка.** Методы-фабрики только создают, заполняют и возвращают — печатать им нечего. Создание объекта внутри одного метода и возврат его наружу — это return для объекта: `return book`.

Теперь перепишите `Program.cs` целиком. **Требования к классу Program.**

- класс Program с методом `public static void Main()` — официальной точкой входа: с него начинается выполнение программы;
- в начале Main: создать Library и Printer; создать три книги переменными book1, book2, book3 вызовами `DataInitializer.MakeBook(1)`, `MakeBook(2)`, `MakeBook(3)`; двух читателей reader1 и reader2 через `MakeReader("Анна Смирнова", "101")` и `MakeReader("Борис Кузнецов", "102")`; зарегистрировать все пять объектов в библиотеке методами RegisterBook и RegisterReader;
- меню живёт в цикле `while (running)`, где running — bool-переменная со значением true; на каждом повторе печатается пустая строка, заголовок «=== Меню библиотеки ===» и шесть пунктов: 1 — показать книги, 2 — показать читателей, 3 — выдать книгу, 4 — вернуть книгу, 5 — статистика, 0 — выход;
- выбор читается вызовом `InputHelper.ReadInt("Ваш выбор: ")`, действие выбирается цепочкой if / else if по значению choice;
- пункт 1: печатает линию `Line(30, "-")`, затем `PrintBook(book1, 1)`, `PrintBook(book2, 2)`, `PrintBook(book3, 3)`;
- пункт 2: `PrintReader(reader1, 1)` и `PrintReader(reader2, 2)`;
- пункт 3: печатает книги, спрашивает «Номер книги: » и «Номер читателя: » через ReadInt; цепочкой if / else if выбирает книгу по номеру (1 — book1, 2 — book2, 3 — book3) и читателя (1 — reader1, 2 — reader2); если оба найдены — `library.Issue(book, reader)`, любой другой номер — «Книга или читатель не найдены»;
- пункт 4: спрашивает номер книги, находит её той же цепочкой if; нашлась — `library.Return(book)`, иначе — «Книга не найдена»;
- пункт 5: вызов `StatsHelper.PrintSummary(library)`; пункт 0: ставит running в false — цикл заканчивается; любой другой номер — «Нет такого пункта меню»;
- после цикла печатается «До свидания!».

**Подсказка.** Цикл while повторяет блок, пока условие истинно; в отличие от for у него нет счётчика — выходом управляет сама переменная running, которую переключает пункт 0. Для выбора по номеру удобно завести временные переменные `Book foundBook = null` и `Reader foundReader = null`, заполнить их цепочкой if / else if, а в конце проверить `foundBook != null` — null из раздела 3.8 здесь и работает. Два условия соединяются операцией «и» — `&&` — например, в условии `foundBook != null && foundReader != null`.

### 6.1. Чек-лист готовности

1. Проект создан в терминале командой `dotnet new console` и открывается в VS Code.
